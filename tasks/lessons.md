# Lessons

## 2026-09-16 · 首发实现

- **冒烟测试的预期要从真实状态推导，不要凭想象。** 第一轮 29 项里 12 项“失败”全是我写错了预期（把 A 的副本当成 C、`lastAccessed` 的上一 Tab 是 A 不是 C、`windowId` 为 undefined 时 `tabs.query` 返回所有窗口）。写断言前先打印一次实际状态，再固化。
- **品牌版 Chrome 不加载 `--load-extension`。** popup 页能打开但 `chrome.runtime` 为 undefined，看似“消息不通”，实为扩展根本没装。用 Chrome for Testing / Chromium。
- **离屏文档里 `execCommand('copy')` 需要 `clipboardWrite` 权限**，否则在无用户手势时静默返回 false。权限表要和实现同步写进方案与 README。
- **设置页运行在标签页里。** 用“sender 有 tab 就是内容脚本”判断来源会把设置页拒掉；要按 `sender.url` 的 `chrome-extension://` 前缀判断。
- **macOS 上 `ctrlKey` 是 MacCtrl，不是 Ctrl。** 迁移旧配置、写测试脚本时都要按平台生成组合键，否则监听永远不命中而界面却显示“已启用”。
- **让子代理做独立代码审查很划算。** 10 条意见里 9 条成立（任务异常未收尾、适配脚本跳转后丢失、设置并发写入等），都是单元测试的假 Chrome 抓不到的。

## 2026-09-16 · 用户反馈（第一批）

- **UI 用 React，不要为了“无构建”选原生 DOM。** 我在方案 8.1 / R20 里替用户做了“原生 JS、不引入框架”的默认决策，被推翻。教训：技术栈选型（框架、语言、构建）不属于可以默认的“常规工程细节”，要么沿用用户已知偏好（TypeScript，见记忆），要么明确请示。
- **架构文档是交付物的一部分。** 实现完成后只有 README 和产品方案，没有面向开发者的架构说明；以后任何多模块实现都要同时产出 docs/ARCHITECTURE.md。
- **产品从第一天就要考虑被发现（SEO / GEO）和商业化。** 我把这两项当作“后续”而完全没写。以后做产品方案时，传播与盈利路径必须是首发章节，即使首发不启用也要预留钩子（落地页、结构化数据、llms.txt、权益/付费开关）。

## 2026-09-18 · 用户反馈（第二批，界面）

- **面板要紧凑、图标化。** 搜索不是主路径，收进标题右侧的图标；动作用九宫格方块 + 按压塌陷反馈；只剩一个按钮的区块并入动作区。
- **设置页导航放侧边**；一行里不要放多个文字按钮，把可点击的目标合并成一个（点键位本身即录入，悬停出现清除）。
- **能力取舍要问价值差**：填入与自己复制差别不大，就降级而不是并列展示。
- **贴合网格不要用「每格独立描边」实现。** 用容器背景透过 1px grid gap 形成分隔线，四边天然不与外框重线，也不必按 nth-child 去掉某一侧边框。
- **删界面要连带删后端。** 移除最近使用区块时，`PanelState.mru`、`activate-tab` 消息、`tabOps.mruList` 都会变成死代码，必须一起清掉并同步方案的功能地图。
- **圆形加放射线会被读成太阳。** 设置入口宁可用滑块图标，齿轮要画出真实齿廓才不会和深色模式切换混淆。
- **展开类交互要原地生长，不要在下方另开一行。** 用绝对定位加 width 过渡，让圆形按钮长成覆盖整行的胶囊，比「点按钮后下方冒出输入框」自然得多。
- **圆角盒子禁止只加单边 border（项目硬规则）。** 那条边会露出圆角之外，像渲染错误。方向性指示改用背景填充，或用不带圆角的独立元素画指示条。已在 `scripts/check.mjs` 加入自动校验，并用反向测试确认能拦住回归。
- **视觉轻重要实测，不能靠估算。** 虚线空位写的是 26px 宽、按键芯片是内容宽度，实测 22.9px，于是空位反而更重。把断言写成「实测空位不大于芯片且等高」，回归就拦得住。
- **等高不等于等重。** 填充芯片的墨量只有内部文字，空心描边却占满整个高度，所以「同高」反而显得更大。空位应保留相同占位空间，但画更小的矩形。
- **`min-height` 会覆盖 `height`。** 把空位和文本芯片放在同一条共享规则里，导致我设的 10px 高度完全无效，实测才发现。
- **小尺寸元件不要用模糊阴影表达按下。** 78px 高的格子上 `inset 0 2px 6px` 会糊成一片灰雾。改用底色加深 + 1px 实线 + 内容位移 1px，干净得多。
- **测 `:active` 要用 CDP 的 `CSS.forcePseudoState`，不要在生产 CSS 里加测试专用类。** 我一度加了 `.is-pressed` 当测试钩子，后来用强制伪类替代，生产样式恢复干净。
- **扩展页面可能因竞态落在 neterror 页。** 调试时出现 `document.activeElement` 为 `BODY.neterror` 才发现；冒烟现在会检查关键元素并重载重试。
- **无头页面里 CSS 过渡不推进，`getComputedStyle` 读到的是过渡起点。** 症状是拿到 `rgba(0,0,0,0) 0px 0px 0px 0px inset` 这种「透明且零偏移」的值。界面断言应先注入 `transition: none !important` 再测目标值。
- **`element.click()` 不一定被 React 接到，用 `Input.dispatchMouseEvent`。** 真实输入事件才稳定，这也更接近用户行为。
- **间歇性失败要跑够次数再判定。** 我一度以为搜索断言的失败是被相邻测试影响，实际是环境抖动；改成确定性写法后连跑四次才敢说稳定。
- **同一种视觉元件只能有一条 CSS 规则。** 浏览器快捷键与网页快捷键各写了一条近似规则（padding 2px 对 3px、圆角 4 对 5），高度差 2px。合并成一条并写死高度，再用冒烟断言两列盒子完全一致。
- **长得一样就必须行为一样。** 我把两列键位统一成同一个盒子之后，不可点击的那一列立刻变成误导。要么统一可点击，要么外观就得区分。
- **一列只重复其他列的信息就该删掉。** 快捷键表的「状态」列大部分内容从键位列就能看出，只有少数问题态有价值；把那几种改为就地提示，整列删除。
- **两个按钮就必须回答「哪个是主」。** 浮动组件原本是填入 + 发送，还用金色区分主次；改成单动作后，主次配色的问题自然消失。能力收敛常常同时解决视觉问题。
- **默认顺序应由数据源的数组顺序决定，不要在多处硬编码。** 把 ChatGPT 提到 `BUILTIN_TARGETS` 首位后，默认值、命令顺序、右键菜单、浮动组件全部自动跟随，只需改一处加一处 fallback。
- **不要靠 `cat >>` 往样式表追加，会累积重复规则并静默覆盖。** popup.css 一度有两份完整的 tile 规则块，我改了前一份却看不到效果，截图才发现。已在 `scripts/check.mjs` 加入按 `@media` 作用域的重复选择器校验。
- **改完 UI 一定要截图确认，不能只看代码通过。** 这次正是截图暴露了「改了但没生效」。
- **一种控件不能既服务 6 个又服务 16 个。** 正方形方块在六个动作时好看，十几个就成了墙；紧凑行在两种数量下都成立，不需要按数量切换布局。
- **面板里的标签要按上下文省略主语。** 「当前 Tab 左移」在面板里只需「左移」；完整名称留给设置页和搜索结果。

## 2026-09-22 · 用户反馈（第八批）

- **同一批对象不要分成两个栏目枚举。** 设置页的「快捷键」和「常用动作」列的是同一批动作，用户要来回对照。合并成一张表，固定与绑定在一行内完成。
- **不要依赖浏览器的收藏图标缓存做区分。** Chrome 的 `_favicon` 对未访问过的站点返回同一个默认地球图标，新装用户看到的还是「两个目标一个图标」。改用确定性的字母加配色标记，顺带省掉一个权限。
- **叠加徽标要放在主体外侧。** 放右下角会压住第二个字母，移到右上角且大部分位于方块之外才不挡内容。
- **断言唯一性前先想清楚「按什么维度唯一」。** 目标标记按行看必然重复（前往与发送各一行），按目标看才唯一。
- **表格单元格上不能加 `display: flex`（项目硬规则）。** `th` / `td` 一旦变成 flex 容器就脱离表格格式化上下文：`colSpan` 失效、文字竖排、底边与同行其他单元格错位。要横向排布就在单元格内部再套一层容器。同一个错误我犯了两次（分组行的 th、动作名的 td），现已加冒烟断言：分组行必须横跨全表、同一行所有单元格底边必须齐平，并用反向测试验证过能拦住。

## 2026-09-23 · 网页内动作面板与冒烟测试卡死

- **测试框架的每个远程调用都必须有超时，整轮必须有看门狗。** DevTools 协议调用没有超时上限时，一个不响应的渲染进程会把整套测试拖成永久挂起，看起来像扩展有 bug。加上超时之后，同一个故障立刻变成「Runtime.evaluate timed out on Overlay — <具体表达式>」，定位从几十分钟缩短到一次运行。
- **先确定故障在「我们的代码」还是「运行环境」，再谈修复。** 我在猜测上花了太久（存储回环、React 死循环、权限事件递归都猜过）。真正有效的是二分：把 `show()` 削减到空函数后页面照样卡死，一步就排除了全部产品代码。**下次遇到疑似死循环，第一件事就是把可疑代码整段停掉，而不是逐行阅读。**
- **`ps` 的 %CPU 是进程生命周期均值，不是瞬时值。** 我据此误判「渲染进程在空转」，白追了一轮。要瞬时值用 `top -l 2`。
- **V8 调试器无法中断，说明忙的不是 JS。** `Debugger.pause` 没有反应时，别再找死循环的 JS 了。
- **对照组要和失败路径逐字一致，只差一个变量。** 我的对照组在鼠标移动和按键之间多了一次 sleep，结果对照组一直通过，掩盖了真正的差异。差异找出来才发现问题出在输入事件的时序上。
- **无头 Chrome 不适合驱动输入事件。** 派发输入后渲染进程会停止响应 DevTools 协议，连新建的调试会话都连不上；同一套断言有头模式全绿。冒烟测试已改为默认有头，`HEADLESS=1` 才无头。
- **不要让测试把扩展页面当消息通道。** 后台化的扩展页会停止执行，而所有扩展页共用一个渲染进程，一个卡住会连累其余（options 页因此连 HTML 都没解析）。消息改由 service worker 里的测试钩子发出；真实的 popup 失焦即关闭，本来就不该有「长期后台存在的 popup」。
- **封闭 Shadow DOM 必须保留 `attachShadow` 的返回值。** `host.shadowRoot` 是 null，丢了引用就再也拿不到，滑选会静默命中不到任何行。

## 2026-09-23 · 径向轮盘

- **圆环上的「等宽缝隙」不能用等角度切。** 弧长 = 半径 × 角度，切固定角度会让缝隙在圆心处窄、在外缘宽。要等宽就得为每个半径反算角度：`asin(缝宽 / 2 / 半径)`。这是用户一眼看出来的，我做的时候没想到。
- **方向型选择要和距离解耦。** 轮盘的扇区由 `atan2` 的方位决定，距离只判断「是否越过死区」。这样甩多远都不影响判定，也就不需要瞄准，贴边、超出轮盘都无所谓。
- **把面板夹进视口后，指针就不在圆心了。** 贴角召出时这会凭空预选一瓣，所以打开后必须先等一次鼠标移动才允许选中。
- **白底页面上，白色的磨砂玻璃等于没有。** 想让它在任何页面上都有边界，玻璃本身要带一点灰调，别指望阴影。
- **区分「面」比区分「线」耐看。** 用户否掉了扇区描边和金色指示弧之后，改成「浅色面板 + 露出底盘做缝隙 + 选中换填充」，立刻干净了。默认别加描边。
- **修饰键不该用「按住多久」单独当触发条件。** ⌘ / Alt 是系统与浏览器组合键的前半段，用户按住它们犹豫是常态。真正的分界线是「手在不在鼠标上」：长按只上膛，鼠标一动才显形，敲组合键时永远不会误弹。
- **隐藏 UI 时要把状态也渲染出去。** `hide()` 只清了内部变量没重渲染，DOM 里留着上一次的高亮；下次打开会闪一帧旧选中，测试读 DOM 也会读到假值。
- **冒烟脚本必须拒绝连上遗留的浏览器。** 上一次运行的 Chrome 占着调试端口时，脚本会连上那个**旧浏览器**，于是一整批标签断言对着别人的标签失败，看起来像代码坏了。启动前探一次端口，占用就直接报错退出。
- **UI 测试要瞄真实元素，别瞄算出来的坐标。** 用「圆心 + 角度 + 距离」算点，等于把产品的布局假设抄进测试，圆心量错一次就全盘皆错；直接量那一瓣图标的位置再把指针移过去，既稳又更接近用户的实际动作。
- **浅色页面会把「透明」变成「高亮」。** 深色浮层上用低透明度表示「不可用」，在白底网页上反而更亮、更抢眼。状态要落在实体元素（徽章）上，不要落在透出页面的那一层。
- **整份重写样式表时，最容易丢的是最不起眼的那条规则。** 我重写 overlay 样式时漏掉了 `.dial { position: absolute }`，SVG 掉回普通流，画面整个错位，但我第一反应却去怀疑 `backdrop-filter` 的层叠。重写后先逐条对照旧文件的选择器清单，比事后猜渲染便宜得多。
- **`backdrop-filter` 会开启自己的层叠上下文。** 需要画在它上面的兄弟元素要显式给 `z-index`，否则会被采样进模糊里。
- **有头模式下 `Page.captureScreenshot` 会等窗口的合成器表面。** 窗口不在最前时这个调用永远不返回，`fromSurface: false` 也救不了。改用 `Page.startScreencast` 取一帧即可，它不走那条路径。顺带：截图是诊断手段，不该让整套测试失败。
- **纯白的测试页验证不了磨砂效果。** 半透明加模糊，在白底上和纯色底板长得一模一样。测试页要放几块饱和色，截图才有诊断价值——这次正是因为测试页全白，我以为模糊生效了，用户一看就说没有。
- **UI 测试的每个操作辅助函数都该自带「回到已知状态」。** 手势类断言依赖前一步的残留状态，失败起来无从复现；让 summon 每次先关面板、先松键，再重试，波动就消失了。
- **两个界面画同一个东西时，共用的应该是几何而不是外观。** 设置页的轮盘和网页里的轮盘视觉完全不同（一个磨砂深色、一个扁平浅色），但「第几瓣朝哪个方向」必须一模一样，所以导出的是 `sectorPath` 与 `slotPercent`，样式各写各的。共用样式反而会逼出一堆覆盖规则。
- **已经模糊过的像素没法靠往上叠东西还原。** 想让 `backdrop-filter` 只作用在一部分区域，唯一的办法是让承载滤镜的那个元素本身不覆盖其余部分——`mask` 会连同被过滤的背景一起裁掉。
- **「复用」在用户眼里是同一个组件，不是同一套坐标。** 我自作主张只共用几何、样式各写各的，结果两个轮盘长得不一样，用户一眼就否了。跨界面复用时，默认应该连样式一起复用；确实需要适配的，用外层容器去兜（`transform` 缩放顺带解决了固定定位的包含块问题），而不是另起一套。
